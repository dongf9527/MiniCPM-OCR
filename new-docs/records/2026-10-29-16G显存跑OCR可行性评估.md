---

## 1. 背景与目的

深度评估报告(见 `../evaluation/MiniCPM-OCR-深度评估报告.md`)给出的标准部署路径(vLLM BF16 + DSpark)显存门槛 ≥24 GB,而当前可用资源为 16 GB 单卡。本记录回答两个问题:① 16G 下能否跑起来、走哪条路径;② 对应的可执行部署形态是什么。前提约束:无并发需求,吞吐指标退居其次,首要是"稳定跑通、质量不打折"。

## 2. 关键结论

1. **16G 可以跑,且有质量余量**。放弃 vLLM BF16(≥24 GB)后,官方维护的低配路径 llama.cpp + GGUF 完全覆盖 16G:1.0 解析引擎(权重 1.4 GB + mmproj 0.86 GB)在收紧上下文后约 4–6 GB;再叠加 Jev 判别引擎(约 5–8 GB)共卡约 12–14 GB,仍在 16G 内。
2. **无并发与 llama.cpp 天然匹配**。llama-server 默认单请求串行,官方 llama.cpp 指南原样要求 SDK 侧 `pipeline.queue_mode=serial` + `pipeline.max_workers=1`——不存在"为省显存而牺牲并发"的折损,参数即官方推荐值。
3. **质量优先选 F16 GGUF**(与 BF16 精度等同);显存再紧可换 **Q8_0**(775 MB,官方口径:表格无损、密集文本近似无损);**Q4_K_M 不建议**(密集文本/代码有可见退化)。Jev 目前无官方 GGUF,需本机按官方文档转换(脚本已封装)。
4. **版面模型默认走 CPU**,不占显存(官方 llama.cpp 指南同款配置);16G 富余时可切 GPU 换取版面速度。
5. **代价**:无 DSpark 投机解码(llama.cpp 不支持),吞吐显著低于 vLLM——单页秒级~分钟级(参考:官方 5090 单表约 1.0 s;纯 CPU 约 21 s/表)。无并发场景下该代价可接受;后续若有吞吐需求再评估 vLLM AWQ 路线(见 §5 待验证)。

## 3. 支撑数据:四条路径显存对比

| 路径 | 显存估算 | 16G 判定 | 依据 |
|---|---|---|---|
| vLLM BF16 + DSpark,ctx 40960 | ≥24 GB | ❌ | 官方门槛;验证机 5090 32GB |
| vLLM BF16 降参(ctx 16384 + util 0.7) | ~20 GB(估) | ❌ 仍超 | 官方 FAQ OOM 处置参数,外推 |
| **llama.cpp F16 GGUF(ctx 8192)** | **1.0 引擎约 4–6 GB** | ✅ 首选 | 官方"4–6 GB"口径 + 权重体积推算;官方 5090 实测 ctx 40960 约 26 GB,反证 ctx 是显存大头、收紧即可回落 |
| llama.cpp 纯 CPU | 0 GB | ✅(慢) | 官方 ~21 s/表(48 线程) |

Jev 补充:2B 判别模型,官方部署文档环境要求**显存 ≥8 GB**(bf16 权重约 4 GB + mmproj + KV cache);官方示例 ctx 32768,共卡 16G 建议降到 16384(判别请求为单次前向、无生成,上下文消耗有限)。共卡显存预算:

| 组件 | 预算(估) |
|---|---|
| 1.0 引擎(F16,ctx 8192) | 4–6 GB(实机 RTX 5080 实测 **3.9 GB**) |
| Jev 引擎(bf16,ctx 16384) | 5–8 GB |
| 版面模型(默认 CPU) | 0 |
| **合计** | **12–14 GB(余 2–4 GB)** |

OOM 降档顺序(共卡时):`JEV_CTX` 16384→8192 → `OCR_CTX` 8192→4096 → 版面保持 CPU → 两引擎按需起停不同时驻留。

## 4. 落地形态:workspace/deploy-16g/ 脚本包

已按协作规则将部署脚本放入 `workspace/deploy-16g/`(编号即执行顺序):`00` 体检 → `10` 编译 llama.cpp(CUDA)→ `11` 下载权重 → `12` Jev 转 GGUF → `20/21` 起引擎 → `22/23` Jev 评分服务(调上游 `setup_render.sh`/`start_render_score.sh`,不改上游文件)→ `30` SDK 环境(默认 CPU paddle)→ `40` 一键解析(串行,`JEV_ENABLED=true` 时以 `tts.rm_input_form=ternary` 对接评分服务)→ `50` 冒烟测试 → `90` 停止。生成物(llama.cpp/、gguf/、venv-*/、run/)已 gitignore,不入库。
